> **Supersession Notice**:
> The initial prototype used the legacy SIH25076 6-subindex model ($82 \rightarrow 68 \rightarrow 86$ with $0.30$ weight).

## 2. Core Judge Defense Questions & Answers

### Q1: "Is this Farm Health / Risk Score generated by an LLM?"
> **Answer**:
> **"Absolutely not. The LLM never touches the score calculation.**
> The score is computed by a 100% deterministic, pure mathematical function in Python domain code with zero I/O, zero random state, and zero LLM calls:
>
> $$\text{Risk Score} = \sum_{i=1}^4 w_i \times S_i$$
>
> The four sub-indices and their exact weights are:
> 1. **`active_problem_severity` (Weight: 0.40 — Largest Weight Anchor)**: Deducts for open diseases and pests (Early: $-30$, Moderate: $-55$, Severe: $-80$).
> 2. **`environmental_risk` (Weight: 0.25)**: Evaluates live temperature and relative humidity deviations against crop-specific ideal bands (or baseline anchor $70$).
> 3. **`monitoring_recency` (Weight: 0.15)**: Decays at $5.0$ points per day without scans ($100$ on fresh scan, $95$ upon agronomist verification).
> 4. **`treatment_response` (Weight: 0.20)**: Quantifies recovery trajectory (`got_worse`: $40$, `no_change`: $50$, neutral baseline: $70$, `improved`: $90$, confirmed resolution: $95$).
>
> Weights sum to exactly $1.00$ ($0.40 + 0.25 + 0.15 + 0.20 = 1.00$). The math is audited and reproducibly proven in `tests/domain/test_health_score.py::test_sih26131_reconciliation`."

### Q2: "Can you prove the exact score transitions during the demo?"
> **Answer**:
> **"Yes. Every score movement is directly traceable to an input event:**
>
> 1. **Baseline Onboarding Scan ($82$ / GOOD)**:
>    $$\text{Score} = 100(0.40) + 70(0.25) + 70(0.15) + 70(0.20) = 40.0 + 17.5 + 10.5 + 14.0 = \mathbf{82.0}$$
>
> 2. **Early Disease Diagnosis ($82 \rightarrow 73$ / WATCH)**:
>    - Bacterial Leaf Blight detected (Early penalty $-30 \rightarrow$ `active_problem_severity` drops to $70$).
>    - Fresh scan recorded (2 days $\rightarrow$ `monitoring_recency` rises to $90$).
>    $$\text{Score} = 70(0.40) + 70(0.25) + 90(0.15) + 70(0.20) = 28.0 + 17.5 + 13.5 + 14.0 = \mathbf{73.0}$$
>
> 3. **Follow-Up 'Got Worse' ($73 \rightarrow 57$ / POOR)**:
>    - Severity promoted to Moderate (Penalty $-55 \rightarrow 45$).
>    - Treatment response penalized to $40$.
>    $$\text{Score} = 45(0.40) + 70(0.25) + 90(0.15) + 40(0.20) = 18.0 + 17.5 + 13.5 + 8.0 = \mathbf{57.0}$$
>    - Drops below $60 \rightarrow$ Triggers automated Rule-3 escalation to KVK Agronomist.
>
> 4. **Agronomist Verified Resolution ($57 \rightarrow 91$ / EXCELLENT)**:
>    - Problem marked resolved $\rightarrow$ severity recovers to $100$.
>    - Verified follow-up scan within 1 day $\rightarrow 95$.
>    - Confirmed expert treatment resolution $\rightarrow 95$.
>    $$\text{Score} = 100(0.40) + 70(0.25) + 95(0.15) + 95(0.20) = 40.0 + 17.5 + 14.25 + 19.0 = 90.75 \rightarrow \mathbf{91}$$"

### Q3: "What prevents the AI from hallucinating chemical dosages or bad advice?"
> **Answer**:
> **"We enforce two immutable architectural gates in Python backend services — not in prompt instructions:**
>
> 1. **Confidence Gate (`CONFIDENCE_GATE = 0.70`)**:
>    - If image diagnosis confidence is below $0.70$, the backend **refuses** to emit automated advice. It immediately compiles an escalation case and routes the farmer to a human KVK agronomist.
>
> 2. **RAG Relevance Threshold & Zero-Fabrication Policy (`RAG_RELEVANCE_THRESHOLD = 0.60`)**:
>    - Retrieval queries against our curated ICAR Package of Practices (PoP) knowledge base in pgvector must score above cosine similarity cutoff.
>    - If no relevant chunk matches, the engine returns an explicit `no_relevant_source` error and offers escalation. The LLM is never permitted to synthesize unverified chemical treatments from base training weights."

---

### Q4: "How does the system handle government land registry integration failures?"
> **Answer**:
> **"Bhoomi adopts a resilient Human-In-The-Loop (HITL) architectural pattern:**
> When the cadastral land registry API is unreachable or returns unlisted survey records, the farm is placed in `unverified_pending_review` status and routed to the Taluk Revenue Officer queue (`taluk_erode`).
> Crucially, **farmer advisory, disease diagnosis, and health tracking are never blocked** while land verification is pending."
